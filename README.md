# اسرار ازل

وب‌اپ آنلاین: https://miadjaberi.github.io/asrar-azal/

## اصول پروژه
- اجرای آنلاین؛ هیچ قابلیت آفلاین یا پاسخ جایگزین آفلاین در Service Worker وجود ندارد.
- ظاهر، چیدمان و محتوای فعلی باید حفظ شوند.
- فایل‌های اصلی روی GitHub Pages میزبانی می‌شوند.
- Supabase برای محتوای زنده، ورود مدیر و ذخیره تصاویر در نظر گرفته شده است.

## راه‌اندازی Supabase (پس از ساخت پروژه)
1. در Supabase یک پروژه بسازید.
2. فایل `supabase/migrations/20261120000000_initial_online_backend.sql` را در SQL Editor اجرا کنید.
3. از Project Settings -> API، مقدار Project URL و Publishable key (یا anon public key قدیمی) را بگیرید.
4. این دو مقدار را فقط در `supabase-config.js` وارد کنید. کلید service_role/secret هرگز نباید در مرورگر قرار گیرد.
5. در Authentication -> Users یک کاربر مدیر بسازید.
6. در SQL Editor، ایمیل واقعی همان مدیر را جایگزین کنید و دستور زیر را اجرا کنید تا نقش فقط در app_metadata ثبت شود:

```sql
update auth.users
set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb) || '{"role":"admin"}'::jsonb
where email = 'YOUR_ADMIN_EMAIL';
```

7. کاربر مدیر یک‌بار خارج و دوباره وارد شود تا JWT جدید با نقش admin دریافت کند.
8. برنامه پس از پیکربندی، محتوای عمومی را از جدول `site_content` می‌خواند. پنل مدیریت با ایمیل/رمز Supabase وارد می‌شود و ذخیره محتوا و آپلود تصاویر را به Supabase می‌فرستد.

## امنیت
- جدول محتوا برای بازدیدکنندگان فقط خواندنی است.
- نوشتن محتوا و آپلود/حذف فایل فقط برای کاربری مجاز است که `app_metadata.role=admin` دارد.
- کلید service_role/secret فقط برای محیط امن سمت سرور است و نباید در HTML، JavaScript یا GitHub Pages قرار گیرد.
- این مخزن هنوز هیچ Project URL یا کلید واقعی Supabase ندارد؛ تا ساخت پروژه و تکمیل `supabase-config.js` اتصال واقعی فعال نمی‌شود.

## فروشگاه و سفارش آنلاین

کدهای فروشگاه در شاخه کاری تکمیل فروشگاه آماده‌سازی شده‌اند؛ تا زمان اتصال واقعی Supabase و تست نهایی، این قابلیت‌ها روی سایت زنده فعال محسوب نمی‌شوند.

### راه‌اندازی backend فروشگاه
1. ابتدا migration اولیه `supabase/migrations/20261120000000_initial_online_backend.sql` را در SQL Editor اجرا کنید.
2. سپس migration فروشگاه `supabase/migrations/20261120010000_store_orders_and_private_receipts.sql` را اجرا کنید. این فایل جدول کالاها، تنظیمات تماس/کارت، سفارش‌ها، محدودسازی درخواست‌ها و فضای خصوصی فیش‌ها را می‌سازد و ده کالای فعلی را با قیمت‌های فعلی سایت وارد می‌کند.
3. در `supabase-config.js` فقط Project URL و کلید عمومی پروژه را وارد کنید؛ کلید محرمانه هرگز نباید در سایت قرار بگیرد.
4. تابع `supabase/functions/create-store-order/index.ts` را با نام `create-store-order` در Supabase Edge Functions منتشر کنید. اگر از Supabase Dashboard استفاده می‌کنید، هنگام ساخت تابع گزینه Verify JWT را خاموش کنید؛ اگر با CLI منتشر می‌کنید، تنظیم `verify_jwt = false` از `supabase/config.toml` خوانده می‌شود. تابع خودش ورودی‌ها را اعتبارسنجی و درخواست‌ها را محدود می‌کند.
5. در پنل مدیریت برنامه، تب «اطلاعات پرداخت» شماره تماس، ساعت تماس (پیش‌فرض ۱۸ الی ۲۱)، شماره کارت، نام صاحب کارت و بانک را تنظیم کنید.
6. در تب «مدیریت کالاها» قیمت و مشخصات کالاها را بازبینی کنید. مقادیر اولیه قیمت از متن فعلی فروشگاه استخراج شده‌اند و پیش از فروش باید توسط مدیر تأیید شوند.
7. سفارش‌ها در تب «سفارش‌ها» نمایش داده می‌شوند. مدیر فقط پس از مشاهده فیش می‌تواند پرداخت را تأیید یا رد کند.

### امنیت سفارش و فیش
- ایجاد سفارش و ساخت نشانی بارگذاری فیش از Edge Function سمت سرور انجام می‌شود.
- فیش‌ها در bucket خصوصی `asrar-payment-receipts` ذخیره می‌شوند؛ لینک مشاهده فقط برای مدیر و به‌صورت زمان‌دار ساخته می‌شود.
- بدون بارگذاری موفق تصویر JPG، PNG یا WEBP (حداکثر ۵ مگابایت)، سفارش وارد وضعیت «در انتظار بررسی مدیریت» نمی‌شود.
- وضعیت سفارش برای خریدار فقط با کد پیگیری و شماره تماس همان سفارش قابل مشاهده است.
- کلید `service_role` فقط در محیط امن Supabase می‌ماند و هرگز در فایل‌های عمومی قرار نمی‌گیرد.

## PWA
- Manifest و Service Worker برای نصب‌پذیری وب‌اپ تنظیم شده‌اند.
- Service Worker فقط درخواست شبکه را عبور می‌دهد؛ Cache و offline fallback ندارد.
